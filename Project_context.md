1. The Core Application & Routing (The Front Door)These files are responsible for handling HTTP requests, managing WebSocket/SSE connections, and acting as the bridge between your UI and V's cognitive engine.chat_routes_2.py (API Router)Purpose: The main receptionist for standard, non-streaming chat requests. It spins up new memory instances and hands off the heavy lifting to the background.Key Functions:talk_to_v(): Receives the initial payload, triggers the cognitive graph, and queues background compaction.get_or_create_session(): Checks if an active session exists; if not, pulls the last 5 interactions from the ROM to build a fresh RAMWindow.event_streams_3.py (SSE Streamer)Purpose: The real-time communication pipeline. This is where Server-Sent Events (SSE) stream the AI's tokens, tool statuses, and UI modals directly to the frontend.Key Functions:stream_response(): The heartbeat of the UI. It yields a continuous stream of JSON packets (tokens, status updates, warnings) and safely closes the connection when done.  generate_session_title(): A quiet background worker that asks a lightweight Ollama model to summarize the first prompt into a 3-4 word title.  authorize_command(): The webhook that listens for your frontend "Approve/Deny" clicks to unlock the Blast Gate.  2. The Cognitive Engine (The Brain)This is where the actual LLM logic, planning, and execution happen. It is the most volatile part of the system and requires the strictest guardrails.state_machine_6.py (The Orchestrator)Purpose: Enforces the strict 0-1-2-3 pipeline (Route -> Plan -> Execute -> Synthesize). It prevents the LLM from going off-script by forcing it to output validated JSON plans before running any tools.Key Functions:run_cognitive_graph(): The master loop. It injects memory context (Step 0), asks the Planner LLM for a tool strategy (Step 1), routes those tools through the Blast Gate, and finally asks the Synthesizer LLM to write a conversational response (Step 3).  execute_tool_async(): The sandbox. It catches silent tool failures and executes authorized Python functions (like updating tasks or reading directories).  sanitize_history(): A regex cleaner that strips old JSON tool-call blocks out of the chat history so the LLM doesn't get confused and hallucinate fake tool executions.  3. Memory & Security (The Vault & The Bouncer)A raw LLM is just a stateless calculator. These modules give V her persistence, identity, and safety boundaries.memory/sqlite_rom.py (Long-Term Storage)Purpose: The immutable hard drive. It stores every conversation log, tool execution result, and auto-generated title.Key Components: The SQLiteROM class, which handles SQL transactions to save and fetch context.  memory/ram_window.py (Short-Term Working Memory)Purpose: Prevents token overflow. It holds the active conversation in memory (up to a specific character limit) and tracks the exact row IDs from the database so it knows what to offload.Key Components: The RAMWindow class, which monitors token weight and flags when the context window is getting "critical".agents/compaction.py (The Janitor)Purpose: Runs asynchronously when the RAM gets too full. It takes the oldest messages, summarizes them into a dense fact block, and frees up space without blocking the user's chat experience.Key Components: CompactionEngine and its dedicated SyncOllamaClient.agents/harness/blast_gates.py (Security Harness)Purpose: Stops V from accidentally formatting your hard drive.Key Components: BlastGate, which evaluates the security_tier of any requested tool against a list of safe/unsafe operations, throwing a Human-In-The-Loop (HITL) authorization request for dangerous commands.
